# Notion 단어장 세팅

Notion 데이터베이스를 만들고 이 웹앱과 연결하는 방법입니다. 한 번만 하면 됩니다.

편집은 Notion에서만 합니다. 웹앱에는 단어를 추가·수정하는 기능이 없습니다.

## 1. 데이터베이스 만들기 (CSV 가져오기)

컬럼을 하나씩 만들지 말고 템플릿을 가져오세요. 이름이 한 글자라도 다르면 동기화가 그 컬럼을 못 읽습니다.

1. Notion에서 `가져오기(Import)` → `CSV` 선택
2. [`examples/notion-단어장-template.csv`](../examples/notion-단어장-template.csv) 업로드
3. 빈 데이터베이스가 **23개 컬럼**으로 생성됩니다

템플릿에는 컬럼만 들어 있고 단어는 없습니다. 가져온 뒤 Notion에서 직접 입력하세요.

저장소에는 단어 JSON이 없습니다. 배포할 때마다 Actions가 Notion에서 `public/data/words.json`을 만들어 함께 배포합니다. 그래서 **Secrets가 없으면 배포가 실패합니다**(5절).

### 가져온 뒤 컬럼 타입 바꾸기

Notion은 CSV를 가져올 때 첫 컬럼만 제목으로, **나머지를 전부 텍스트로** 만듭니다. 동기화는 텍스트 상태로도 동작하지만, 아래 넷은 바꿔 두면 Notion에서 필터·그룹으로 쓰기 편합니다.

| 컬럼 | 바꿀 타입 |
|---|---|
| `대분류`, `분류`, `중요도` | 선택 (Select) |
| `태그` | 다중 선택 (Multi-select) |

## 2. 컬럼 레퍼런스

`용어`만 필수이고, **번역은 최소 한 개** 있어야 합니다. 나머지는 비워도 됩니다.

### 개념 공통

| 컬럼 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `용어` | 제목 | **필수** | 한국어 기준 표현. 비어 있으면 동기화가 실패합니다 |
| `대분류` | 선택 | | 비우면 `기타` |
| `분류` | 선택 | | 비우면 `미분류` |
| `암기포인트` | 텍스트 | | 카드 하단 메모 |
| `태그` | 다중 선택 | | 쉼표로 구분해 읽습니다 |
| `추가 언어 JSON` | 텍스트 | | 아래 4절 참고 |
| `중요도` | 선택 | | **앱이 읽지 않습니다.** Notion에서만 쓰는 개인 분류 |

### 언어별

세 언어는 정식 컬럼을 가집니다. 한 행에 셋 다 채워도 되고, 일부만 채워도 됩니다. 번역이 없는 언어로 학습할 때 그 행은 **자동으로 제외**됩니다.

| 중국어 | 영어 | 일본어 | 설명 |
|---|---|---|---|
| `중국어` | `영어` | `일본어` | 표현 자체. 이 칸이 비면 그 언어는 없는 것으로 봅니다 |
| `병음 (Pinyin)` | `영어 발음` | `일본어 읽기` | 발음 표기. **음성으로 읽지 않고 화면에만 표시**합니다 |
| `중국어 예문` | `영어 예문` | `일본어 예문` | 예문 |
| `중국어 예문 해석` | `영어 예문 해석` | `일본어 예문 해석` | 그 예문의 한국어 뜻 |
| `중국어 발음 보정` | `영어 발음 보정` | `일본어 발음 보정` | TTS가 잘못 읽을 때만 채웁니다. 아래 참고 |

예문 해석은 **언어마다 따로** 둡니다. 학습 언어를 영어로 바꾸면 영어 예문과 영어 예문 해석이 함께 나옵니다.

### 발음 보정

음성 엔진이 단어를 잘못 읽을 때만 씁니다. 보정 칸에 적은 글자를 **대신 읽고**, 화면과 검색에는 원래 표현이 그대로 나옵니다. 비워 두면 표현을 그대로 읽습니다. 한국어 기준 표현은 `한국어 발음 보정` 컬럼을 씁니다.

| 언어 | 방법 | 예 |
|---|---|---|
| 중국어 | 독음이 하나뿐인 동음자로 바꾸기 | `宗庙祭礼乐`가 lè로 읽히면 → `宗庙祭礼月` (yuè) |
| 일본어 | 히라가나로 쓰기 | `宗廟` → `そうびょう` |
| 영어 | 소리 나는 대로 철자 고쳐 쓰기 | `Gyeongbokgung` → `Gyung-bok-goong` |
| 한국어 | 표준 발음을 한글로 쓰기 | `신라` → `실라` |

- 병음이나 IPA를 넣지 마세요. 음성 엔진은 이것을 알파벳으로 읽습니다
- 기기·음성마다 틀리는 단어가 다를 수 있습니다. 보정은 **실제로 쓰는 기기에서 들어 보고** 적으세요

## 3. 입력 규칙

**한 행 = 한 개념(뜻) 하나입니다.** 번역이 1:1로 대응하지 않거나 뜻이 여러 개면 행을 나누세요.

- 영어 `bank`의 '은행'과 '강둑' → 다른 행
- 한국어 '사과'(과일)와 '사과'(용서를 구함) → 다른 행

행을 나누면 복습 기록도 뜻별로 따로 쌓입니다. 한 행에 여러 뜻을 몰아 넣으면 TTS가 그 전부를 한 번에 읽습니다.

복습 기록은 **Notion 페이지 ID + 학습 언어**로 저장됩니다. 표현을 고쳐도 기록은 유지되지만, 행을 지웠다가 다시 만들면 새 페이지 ID가 되어 기록이 끊깁니다.

## 4. 새 언어 추가

코드를 고치지 않고 `추가 언어 JSON` 컬럼에 BCP 47 언어 코드로 넣습니다.

```json
{
  "es-ES": {
    "text": "manzana",
    "pronunciation": "",
    "example": "Como una manzana cada día.",
    "exampleTranslation": "나는 매일 사과를 하나 먹는다.",
    "speechText": ""
  }
}
```

- `text`만 필수이고 나머지는 생략 가능합니다. `speechText`는 위의 발음 보정과 같습니다
- 언어 코드는 표준형으로 정규화됩니다. `ZH-cn`이라고 적어도 `zh-CN`으로 묶입니다
- 그래서 **정식 컬럼에 이미 있는 언어는 여기 넣을 수 없습니다**(중복 오류)
- Notion 텍스트 속성의 길이 한계가 있으니 예문이 길거나 언어가 많으면 나눠 담으세요

자주 쓰는 언어가 되면 `scripts/notion.ts`의 `LANGUAGE_COLUMNS` 배열에 항목 하나를 추가해 정식 컬럼으로 올리세요. 언어 이름은 `Intl.DisplayNames`가 자동으로 만들어 주므로 따로 등록할 곳이 없습니다.

## 5. Integration 연결

1. <https://www.notion.so/profile/integrations> 에서 **읽기 권한**만 가진 Integration을 만듭니다
2. 토큰(`ntn_`으로 시작)을 복사합니다
3. 데이터베이스 페이지 → `⋯` → `연결(Connections)` → 만든 Integration 추가

### 데이터 소스 ID 찾기

데이터베이스를 **전체 페이지로 열고** 주소에서 가져옵니다.

```
https://www.notion.so/<워크스페이스>/<32자리 ID>?v=...
                                    ^^^^^^^^^^^^ 이 부분
```

이 값이 `NOTION_DATABASE_ID`입니다. 데이터 소스가 하나면 이것만으로 동작합니다. 여러 개이면 동기화가 "데이터 소스가 여러 개입니다"라고 알려 주며, 그때는 `NOTION_DATA_SOURCE_ID`를 직접 설정해야 합니다.

### GitHub Secrets

저장소 `Settings → Secrets and variables → Actions`:

| 이름 | 필수 |
|---|---|
| `NOTION_TOKEN` | **필수** |
| `NOTION_DATA_SOURCE_ID` | 권장 |
| `NOTION_DATABASE_ID` | 위가 없을 때 |

토큰은 Actions에서만 쓰이며 배포되는 파일에는 들어가지 않습니다. **다만 단어·뜻·메모 등 JSON으로 내보내는 내용은 누구나 볼 수 있습니다.** 개인 정보나 타인의 유료 콘텐츠는 넣지 마세요.

## 6. 동기화 확인

로컬에서 바로 시험해 볼 수 있습니다.

```sh
export NOTION_TOKEN=ntn_...
export NOTION_DATABASE_ID=...
npm run sync:notion
```

성공하면 `public/data/words.json`이 만들어지고 개수가 출력됩니다. 이 파일은 git에 올라가지 않습니다. GitHub에서는 `Actions → Sync Notion and deploy GitHub Pages → Run workflow`로 실행하고, 이후 약 15분 간격으로 자동 시도합니다(예약 작업은 지연·누락될 수 있습니다).

### 실패했을 때

**동기화가 실패해도 이미 배포된 단어 JSON은 그대로 유지됩니다.** 덮어쓰지 않고 중단합니다. 실패하면 저장소에 `sync-failure` 라벨이 붙은 이슈가 자동으로 생기고, 계속 실패하면 같은 이슈에 댓글로 쌓입니다.

| 메시지 | 원인 |
|---|---|
| `한국어 기준 표현이 없는 Notion 페이지` | `용어`가 빈 행. 다른 칸은 채워져 있는데 제목만 비었을 때 |
| `추가 언어 JSON이 올바르지 않습니다` | JSON 문법 오류. 따옴표·쉼표 확인 |
| `…는 기본 컬럼과 중복되어` | 정식 컬럼에 있는 언어를 `추가 언어 JSON`에도 넣었을 때 |
| `데이터 소스가 여러 개입니다` | `NOTION_DATA_SOURCE_ID`를 직접 지정 |
| `Notion 결과가 0개` | Integration이 데이터베이스에 연결되지 않았을 가능성이 큼 |
| `Notion API HTTP 401` | 토큰이 잘못됐거나 만료 |

한 행이라도 잘못되면 **전체 동기화가 실패합니다.** 일부만 반영해 데이터가 어긋나는 것보다 낫다고 보고 그렇게 두었습니다.

> 단어 개수가 갑자기 줄어드는 것은 막지 않습니다. 의도적으로 대량 삭제·재구성할 수 있기 때문입니다.

## 7. 스크립트 데이터베이스 (선택)

관광 안내 멘트나 면접 답변처럼 **긴 글을 처음부터 끝까지 이어 듣는** 기능입니다. 단어장과 별개인 데이터베이스를 하나 더 만듭니다. 화면은 단어장과 별도 페이지 `script/`이며, 설정하지 않으면 스크립트가 없다고만 표시되고 단어장은 그대로 동작합니다.

### 만들기

1. [`examples/notion-스크립트-template.csv`](../examples/notion-스크립트-template.csv)를 가져오기(Import)합니다
2. `언어`, `대분류`는 선택(Select) 타입으로 바꿔 두면 편합니다
3. 단어장과 같은 Integration을 이 데이터베이스에도 연결합니다
4. GitHub Secrets에 `NOTION_SCRIPTS_DATABASE_ID`(또는 `NOTION_SCRIPTS_DATA_SOURCE_ID`)를 추가합니다. 토큰은 `NOTION_TOKEN`을 같이 씁니다
5. GitHub Secrets에 `SCRIPTS_PASSWORD`(12자 이상)를 추가합니다. 스크립트 페이지를 열 때 입력하는 비밀번호입니다

### 비밀번호와 암호화

공개 Pages에 올라가는 `data/scripts.json`은 `SCRIPTS_PASSWORD`로 암호화됩니다(PBKDF2-SHA256 60만 회 + AES-GCM). 비밀번호를 모르면 파일을 받아도 내용을 볼 수 없습니다.

- 스크립트 데이터베이스를 연결했는데 `SCRIPTS_PASSWORD`가 없거나 12자보다 짧으면 **동기화 전체가 실패**합니다. 평문으로 올리지 않기 위해서입니다
- 파일은 누구나 받아 갈 수 있으니 짧은 비밀번호는 무차별 대입으로 풀릴 수 있습니다. 단어 3~4개를 이은 문구를 권합니다
- 스크립트 페이지에서 `이 기기에서 기억하기`를 고르면 비밀번호가 아니라 거기서 만든 키를 브라우저에 저장합니다. `🔒 이 기기에서 잠그기`로 지웁니다
- 비밀번호를 잊었거나 바꾸려면 Secret을 새 값으로 바꾸고 동기화를 다시 실행하세요. 원본은 Notion에 있으니 잃는 내용은 없고, 기기마다 새 비밀번호를 한 번씩 입력하면 됩니다
- 숨겨지는 것은 스크립트 내용입니다. 스크립트 페이지가 있다는 것과 대략적인 파일 크기는 보입니다

| 컬럼 | 필수 | 설명 |
|---|---|---|
| `제목` | **필수** | 앱의 스크립트 목록에 나오는 이름 |
| `언어` | **필수** | `중국어`·`영어`·`일본어` 또는 BCP 47 코드(`es-ES` 등). 본문을 이 언어 음성으로 읽습니다 |
| `대분류` | | 목록에서 제목 옆에 표시. 비우면 `기타` |

### 본문 쓰는 법

행을 열어 **페이지 본문**에 씁니다. 한 스크립트에는 한 언어만 씁니다. 같은 글의 영어판이 필요하면 행을 하나 더 만드세요.

| 블록 | 앱에서 |
|---|---|
| 텍스트, 글머리 기호·번호 목록, 콜아웃 | 본문. 문장 단위로 나눠 차례로 읽습니다 |
| 제목 1·2·3 | 본문(소제목). 읽고, 크게 표시합니다 |
| 인용 (`"` 입력) | **바로 위 문단의 한국어 해석.** 화면에만 표시하고 읽지 않습니다 |
| 그 밖의 블록, 토글 안쪽 내용 | 무시합니다 |

```
景福宫是朝鲜王朝的正宫，建于1395年。      ← 텍스트 블록: 읽음
┃ 경복궁은 조선 왕조의 법궁으로, 1395년에…  ← 인용 블록: 해석으로 표시
```

- 문장은 `。！？.!?`과 줄바꿈 기준으로 동기화할 때 나눕니다. 한 문장이 너무 길면 모바일 음성이 중간에 끊길 수 있으니 적당히 끊어 쓰세요
- 해석(인용)이 첫 본문보다 먼저 나오거나, 본문이 비어 있거나, `언어`가 비면 **동기화 전체가 실패**합니다(단어장과 같은 규칙)
- 스크립트 데이터베이스를 연결했는데 스크립트가 0개여도 실패합니다
- 스크립트 수만큼 Notion API 요청이 늘어납니다. 수백 개 단위가 아니면 문제없습니다
