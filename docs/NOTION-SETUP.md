# Notion 단어장 세팅

Notion 데이터베이스를 만들고 이 웹앱과 연결하는 방법입니다. 한 번만 하면 됩니다.

편집은 Notion에서만 합니다. 웹앱에는 단어를 추가·수정하는 기능이 없습니다.

## 1. 데이터베이스 만들기 (CSV 가져오기)

컬럼을 하나씩 만들지 말고 템플릿을 가져오세요. 이름이 한 글자라도 다르면 동기화가 그 컬럼을 못 읽습니다.

1. Notion에서 `가져오기(Import)` → `CSV` 선택
2. [`examples/notion-단어장-template.csv`](../examples/notion-단어장-template.csv) 업로드
3. 새 데이터베이스가 **19개 컬럼 · 170행**으로 생성됩니다

들어 있는 데이터는 관광통역안내사 중국어 용어 168개와, 한 개념에 여러 언어를 연결하는 방식을 보여 주는 예시 2개(`사과`, `도서관`)입니다. 예시 행은 `태그 = 다국어 예시`로 찾아 지우면 됩니다.

### 가져온 뒤 컬럼 타입 바꾸기

Notion은 CSV를 가져올 때 첫 컬럼만 제목으로, **나머지를 전부 텍스트로** 만듭니다. 동기화는 텍스트 상태로도 동작하지만, 아래 넷은 바꿔 두면 Notion에서 필터·그룹으로 쓰기 편합니다.

| 컬럼 | 바꿀 타입 |
|---|---|
| `대분류`, `분류`, `중요도` | 선택 (Select) |
| `태그` | 다중 선택 (Multi-select) |

## 2. 컬럼 레퍼런스

`용어`만 필수이고, **번역은 최소 한 개** 있어야 합니다. 나머지는 비워도 됩니다.

### 개념 공통

| 컬럼 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `용어` | 제목 | **필수** | 한국어 기준 표현. 비어 있으면 동기화가 실패합니다 |
| `대분류` | 선택 | | 비우면 `기타` |
| `분류` | 선택 | | 비우면 `미분류` |
| `암기포인트` | 텍스트 | | 카드 하단 메모 |
| `태그` | 다중 선택 | | 쉼표로 구분해 읽습니다 |
| `추가 언어 JSON` | 텍스트 | | 아래 4절 참고 |
| `중요도` | 선택 | | **앱이 읽지 않습니다.** Notion에서만 쓰는 개인 분류 |

### 언어별

세 언어는 정식 컬럼을 가집니다. 한 행에 셋 다 채워도 되고, 일부만 채워도 됩니다. 번역이 없는 언어로 학습할 때 그 행은 **자동으로 제외**됩니다.

| 중국어 | 영어 | 일본어 | 설명 |
|---|---|---|---|
| `중국어` | `영어` | `일본어` | 표현 자체. 이 칸이 비면 그 언어는 없는 것으로 봅니다 |
| `병음 (Pinyin)` | `영어 발음` | `일본어 읽기` | 발음 표기. **음성으로 읽지 않고 화면에만 표시**합니다 |
| `중국어 예문` | `영어 예문` | `일본어 예문` | 예문 |
| `중국어 예문 해석` | `영어 예문 해석` | `일본어 예문 해석` | 그 예문의 한국어 뜻 |

예문 해석은 **언어마다 따로** 둡니다. 학습 언어를 영어로 바꾸면 영어 예문과 영어 예문 해석이 함께 나옵니다.

## 3. 입력 규칙

**한 행 = 한 개념(뜻) 하나입니다.** 번역이 1:1로 대응하지 않거나 뜻이 여러 개면 행을 나누세요.

- 영어 `bank`의 '은행'과 '강둑' → 다른 행
- 한국어 '사과'(과일)와 '사과'(용서를 구함) → 다른 행

행을 나누면 복습 기록도 뜻별로 따로 쌓입니다. 한 행에 여러 뜻을 몰아 넣으면 TTS가 그 전부를 한 번에 읽습니다.

복습 기록은 **Notion 페이지 ID + 학습 언어**로 저장됩니다. 표현을 고쳐도 기록은 유지되지만, 행을 지웠다가 다시 만들면 새 페이지 ID가 되어 기록이 끊깁니다.

## 4. 새 언어 추가

코드를 고치지 않고 `추가 언어 JSON` 컬럼에 BCP 47 언어 코드로 넣습니다.

```json
{
  "es-ES": {
    "text": "manzana",
    "pronunciation": "",
    "example": "Como una manzana cada día.",
    "exampleTranslation": "나는 매일 사과를 하나 먹는다."
  }
}
```

- `text`만 필수이고 나머지는 생략 가능합니다
- 언어 코드는 표준형으로 정규화됩니다. `ZH-cn`이라고 적어도 `zh-CN`으로 묶입니다
- 그래서 **정식 컬럼에 이미 있는 언어는 여기 넣을 수 없습니다**(중복 오류)
- Notion 텍스트 속성의 길이 한계가 있으니 예문이 길거나 언어가 많으면 나눠 담으세요

자주 쓰는 언어가 되면 `scripts/notion.ts`의 `LANGUAGE_COLUMNS` 배열에 항목 하나를 추가해 정식 컬럼으로 올리세요. 언어 이름은 `Intl.DisplayNames`가 자동으로 만들어 주므로 따로 등록할 곳이 없습니다.

## 5. Integration 연결

1. <https://www.notion.so/profile/integrations> 에서 **읽기 권한**만 가진 Integration을 만듭니다
2. 토큰(`ntn_`으로 시작)을 복사합니다
3. 데이터베이스 페이지 → `⋯` → `연결(Connections)` → 만든 Integration 추가

### 데이터 소스 ID 찾기

데이터베이스를 **전체 페이지로 열고** 주소에서 가져옵니다.

```
https://www.notion.so/<워크스페이스>/<32자리 ID>?v=...
                                    ^^^^^^^^^^^^ 이 부분
```

이 값이 `NOTION_DATABASE_ID`입니다. 데이터 소스가 하나면 이것만으로 동작합니다. 여러 개이면 동기화가 "데이터 소스가 여러 개입니다"라고 알려 주며, 그때는 `NOTION_DATA_SOURCE_ID`를 직접 설정해야 합니다.

### GitHub Secrets

저장소 `Settings → Secrets and variables → Actions`:

| 이름 | 필수 |
|---|---|
| `NOTION_TOKEN` | **필수** |
| `NOTION_DATA_SOURCE_ID` | 권장 |
| `NOTION_DATABASE_ID` | 위가 없을 때 |

토큰은 Actions에서만 쓰이며 배포되는 파일에는 들어가지 않습니다. **다만 단어·뜻·메모 등 JSON으로 내보내는 내용은 누구나 볼 수 있습니다.** 개인 정보나 타인의 유료 콘텐츠는 넣지 마세요.

## 6. 동기화 확인

로컬에서 바로 시험해 볼 수 있습니다.

```sh
export NOTION_TOKEN=ntn_...
export NOTION_DATABASE_ID=...
npm run sync:notion
```

성공하면 `public/data/words.json`이 갱신되고 개수가 출력됩니다. GitHub에서는 `Actions → Sync Notion and deploy GitHub Pages → Run workflow`로 실행하고, 이후 약 15분 간격으로 자동 시도합니다(예약 작업은 지연·누락될 수 있습니다).

### 실패했을 때

**동기화가 실패해도 이미 배포된 단어 JSON은 그대로 유지됩니다.** 덮어쓰지 않고 중단합니다. 실패하면 저장소에 `sync-failure` 라벨이 붙은 이슈가 자동으로 생기고, 계속 실패하면 같은 이슈에 댓글로 쌓입니다.

| 메시지 | 원인 |
|---|---|
| `한국어 기준 표현이 없는 Notion 페이지` | `용어`가 빈 행. 다른 칸은 채워져 있는데 제목만 비었을 때 |
| `추가 언어 JSON이 올바르지 않습니다` | JSON 문법 오류. 따옴표·쉼표 확인 |
| `…는 기본 컬럼과 중복되어` | 정식 컬럼에 있는 언어를 `추가 언어 JSON`에도 넣었을 때 |
| `데이터 소스가 여러 개입니다` | `NOTION_DATA_SOURCE_ID`를 직접 지정 |
| `Notion 결과가 0개` | Integration이 데이터베이스에 연결되지 않았을 가능성이 큼 |
| `Notion API HTTP 401` | 토큰이 잘못됐거나 만료 |

한 행이라도 잘못되면 **전체 동기화가 실패합니다.** 일부만 반영해 데이터가 어긋나는 것보다 낫다고 보고 그렇게 두었습니다.

> 단어 개수가 갑자기 줄어드는 것은 막지 않습니다. 의도적으로 대량 삭제·재구성할 수 있기 때문입니다.
